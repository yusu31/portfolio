## 決定: パレットは4種を維持し、Day を基準にする

| | 役割 |
|---|---|
| **Day** | **基準**。撮り比べで唯一すべて（緑パッチ・建物4色・白線）が読めていた |
| **Dusk** | Golden を作り直したもの。暖色の光 + 寒色の空 + 長い影 |
| Misty | 建物の明度レンジだけ広げた |
| **Night** | **終章**。空は暗いまま、島側だけ持ち上げた |

- **3種に絞っていない。** 破綻の原因（色相差・明度差の不足）が数値で特定できて直せるため
- **Night を残した理由は、クリスタル球を置くなら夜が最も映えるから。**
  球体と空の ΔE が 100.5 で4種中最大（Day の 84.1 を大きく上回る）。この関係もテストで縛ってある

## 検証ノブ（QA用クエリ）

`MSYS_NO_PATHCONV=1 node scripts/qa-proto-shots.mjs /proto/c <outDir> <plansJson>`
Git Bash からは `MSYS_NO_PATHCONV=1` が必須。ヘッデッド必須。

| クエリ | 効果 |
|---|---|
| `?card=N` | カードを直接指定。**同時に揺れも凍結する**（動きが残ると収束しない） |
| `?at=0〜1` | カード間の移動量 |
| `?pal=N` | 全カードを同じパレットで塗る |
| `?chain=0` | ステージのカードだけ描く |
| `?sky=0` | **上部を横切る構造を切る**（有無を同じ構図で撮り比べる） |

## この方向で確立したこと

- **破綻は語彙ではなく数値で特定する。** 「Night が暗すぎる」と3本ぶん言い続けても直らなかったものが、
  ΔE で測った瞬間に3つの原因に分解できた
- **閾値には壊れていた側の実測値を書き残す。** 「旧 Night 7.0 が塊に溶ける側」と書いてあれば、
  次に緩めたくなったときに判断できる
- **空を背にする物と島を背にする物では、必要な色が違う。** 同じ `post` が島の上では読めて空中では溶ける
