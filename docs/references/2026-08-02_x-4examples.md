## 前回分析の訂正（重要）

SESSION4 では「全例が非写実 → トゥーン化 → 輪郭線が魅力の本体」と結論づけたが、
**実物を見ると輪郭線がはっきりあるのは ① の1例だけ**で、②③④は輪郭線なし。

つまり **「輪郭線が本体」という SESSION4 の仮説は参考例の実構成とズレていた**。
SESSION5 の retrofit 実験（`?toon=1` / `?outline=1`）が「効いてはいるが参考例の魅力にならない」
という結果になったのは、狙う対象そのものを取り違えていたためと考えられる。

## 4例に共通していること（＝移植すべきもの）

1. **パレットが絞られている**
   ②が最も明示的（Day/Golden/Misty/Night）。1画面の色数が少なく、
   全部が1つのトーンに沈んでいる。シェーダーの種類ではなくここが世界観を作っている

2. **カメラが引いている / 被写体が小さい**
   4例とも主役は画面の 1/4 〜 1/8。**現行ポートフォリオはボールとクリスタル球が
   画面を占有していて真逆**。u=0.44 でも u=0.55 でも球が画面の1/3を超える

3. **地面が主役級の面積を持ち、そこに情報が乗っている**
   ①道路の白線・マンホール、②線路と地形、③タイルの目地、④木目とテーブルの縁。
   **現行は地面が単色で無地**。面積は取っているのに情報が無い

4. **密度が高い**
   小物が大量に置かれている。1つ1つは単純な低ポリでよく、物量で画が持つ。
   **現行はオブジェクト間が空いていてガランとしている**

5. **俯瞰が3例、一点透視が1例**
   ②③④はアイソメ寄りの俯瞰。①だけが背面追従＋一点透視。
   いずれも「カメラが世界を見せる」設計で、現行の密着チェイスとは別種

6. **3Dの上に平面UIを重ねる**
   ①のアイコン列、④のHUD。現行の SectionCards と同じ発想なので、ここは既に合っている

### 3本すべてに共通させる作り方の原則

今日の retrofit 失敗の逆をやる。

1. **パレットを先に固定する**（②に倣い章ごとに切り替わる想定で3〜4種用意）
2. **カメラを引く**。主役を画面の1/4以下に収める
3. **地面に情報を乗せる**（模様・白線・目地・小物）。面積が大きいので効果も大きい
4. **密度を上げる**。単純な低ポリを大量に置く
5. **NPR前提でジオメトリから作る**。線を乗せるならベベルを入れ、段を出すなら曲面を持たせる
6. **輪郭線は必須ではない**。①以外は使っていない。パレットと影色で作れるか先に試す
